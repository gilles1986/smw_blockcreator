# BlockCreator v1 — Spec

Vocabulary: see [CONTEXT.md](../../CONTEXT.md). Decisions: [docs/adr](../../docs/adr). Facts about GPS blocks: [docs/research/gps-block-anatomie.md](../../docs/research/gps-block-anatomie.md). UI reference: variant C on branch `prototype/ui` (`prototype/ui/index.html?variant=C`).

## Problem

Writing an SMW custom block means hand-writing 65816 ASM against GPS's offset table: knowing which offset fires when, how to set act-as at runtime (`$1693` + Y), which RAM addresses hold which state, which registers routines destroy, and that offsets fire every frame per contact point. Most blocks people want are simple combinations of the same few behaviours ("solid for sprites, air for Mario", "hurts from the side when ON", "boost Mario away"). The existing generator (Kipernal's Blockreator) cannot re-open its output and has known correctness gaps (muncher side check).

## Goal

A downloadable desktop tool in which a hacker composes a Block from Pieces per Slot — visually, with nested if / else if / else — gets correct, SA-1-compatible GPS ASM, can save it straight into their project, and can re-open any Block the tool generated.

## Users

SMW hackers using GPS, from beginners (never wrote ASM) to experienced (want speed and a Custom ASM escape hatch). Piece authors from the community who extend the Library.

## Scope v1

### Editor (layout = prototype variant C)
- Left sidebar: Block properties (name = file name, description, author, default act-as); Slot rows grouped under Mario and Sprite with a filled dot and a one-line logic summary; "copy" per row; advanced Slots behind a toggle; "Top corner = Top" link; Save buttons at the bottom.
- Right: header with the selected Slot, Piece search, "Copy to…"; Blockly editor (zelos renderer, dark theme) and live ASM preview side by side.
- Toolbox categories by Piece category with colours; toolbox filtered by Slot type (Mario-only / Sprite-only Pieces); search results as a top category.
- Warnings on Blocks: `once` Pieces not followed by a Block-removing Action; missing / outdated Pieces.
- New, Open, New from preset, Save, Save as…, Save to project…. Undo/redo (Blockly's).
- UI language English; strings from `locales/<lang>.json`; locale files dropped into the locales folder appear in the language menu.

### Slots → offsets
| UI Slot | GPS offset | Runtime split |
|---|---|---|
| Mario Top | MarioAbove | — |
| Mario Bottom | MarioBelow | — |
| Mario Left / Right | MarioSide | `$93` (0 = Mario left of the block, 1 = right; disassembly `CODE_00EB77`) |
| Mario Inside | BodyInside + HeadInside | overridden by Head/Body inside if filled |
| Mario Top corner (adv.) | TopCorner | linked to Top by default while empty (`TopCorner:` label on the MarioAbove section; same effect as `JMP MarioAbove`) |
| Mario Head inside / Body inside (adv.) | HeadInside / BodyInside | — |
| Mario Cape / Fireball (adv.) | MarioCape / MarioFireball | — |
| Mario Wall-run feet / body (adv.) | WallFeet / WallBody | only with header `db $37` |
| Sprite Top / Bottom | SpriteV | `!AA,x` sign (≥0 = touches top) |
| Sprite Left / Right | SpriteH | `!B6,x` sign (≥0 = touches left side) |

Header is `db $37` iff a wall-run Slot is filled, else `db $42`. Sprite sections call `%sprite_block_position()` before any code. Empty offsets are a bare `RTL`.

### Generated file
1. `;@bc-format <n>`, `;@bc-model <json>`, `;@bc-checksum <hash of code below>` — machine header (ADR 1).
2. Human header: name, "generated by BlockCreator <version>", `Insert with act as <default>`, description, credits of used Pieces, routines needed.
3. Code: jump table, one section per offset, `print "<description>"`.
The model JSON stores Block properties, links, and per Slot a tree of `{piece id, version, params, children}` — never Piece code.

### Pieces and Library (ADR 3)
- `library/actions/<id>/`, `library/conditions/<id>/`: `piece.json` + `code.asm`.
- Manifest: `id`, `version`, `kind` (action|condition), `category`, `name`, `description`, `author`, `credits?`, `icon?` (unused in v1), `slots` (mario|sprite|any), `params[]` (name, label, type: number{min,max,format hex|dec} | enum{options} | bool | map16 | sprite | sound | text | multiline, default), `once`, `removesBlock`, `clobbers` (A|X|Y), `routines[]`.
- Template: Mustache subset — `{{param}}`, `{{#if param}}…{{else}}…{{/if}}`, `{{#each list}}`, `{{label "name"}}` (unique per instance), `{{false}}` (Conditions only: jump target when false), helpers for hex formatting and signed bytes.
- Built-in Library ships with the app; user Library path configurable; same id → user wins.
- `library/routines/bc_*.asm`: tool-provided GPS routines (e.g. `bc_kill_touching_sprite`, `bc_holding_sprite`).
- `library/presets/*.asm`: 8–10 ready-made Blocks (they are normal generated Blocks).

### Generator rules
- Per-Slot code = statement list; `controls_if` → condition wiring with generated labels; Conditions jump to `{{false}}`; AND/OR/NOT by label rewiring; branches out of range are rewritten as inverted branch + `JMP` (or a trampoline).
- Around a Piece: save/restore registers listed in `clobbers` that matter in that Slot (Y always — act-as high byte; X in sprite and fireball Slots — sprite index).
- All code SA-1 compatible (`|!addr`, `|!bank`, `!sprite_*` / `!9E`-style defines from GPS `defines.asm`).
- Deterministic: same model + same Library → byte-identical output (checksum stable).

### Validation
- "Check" button and automatic check before every save: assemble the generated block with Asar inside a harness that provides GPS defines and routine stubs; map errors back to Slot and Piece by line.

### Project integration
- Open project: pick the romhack folder or GPS folder; detect `gps.exe` + `list.txt`; remember recent projects. Also detect PIXI `list.txt` for custom sprite names.
- Save to project: target folder (default `blocks/blockcreator/`); optional `list.txt` entry `<map16>:<default act-as> <path>`: Map16 page selector + dropdown listing each number on that page with the file occupying it or "free"; update an existing entry for the same file instead of duplicating; insert before `@dsc`; write `list.txt.bak` before any change.
- Routines: copy missing `bc_*` routines into `GPS/routines/` after asking; never overwrite silently, ask on version mismatch. Save as… shows the list of routine files to copy instead.
- The tool never runs GPS or Callisto; it tells the user to run GPS / Callisto "Update".

### Open / re-import
- Parse only the `;@bc-*` header. Checksum mismatch → "This file was edited by hand; saving will overwrite those edits."
- Piece missing → greyed placeholder keeping its params; saving blocked until replaced/removed.
- Piece newer than recorded → notice listing changes (old → new version) before regenerating.
- Files without a `;@bc-model` header → "Not a BlockCreator block" (import of foreign blocks is v2).

### v1 Library (built-in)
Actions — Physics: act as (025 / 130 / 12F / 1F0 / 100 / custom), boost Mario (8 directions or away from block; X/Y strength; set/add; presets), push sprite (same options), turn sprite around, set sprite state. Damage: hurt Mario (muncher-correct side check), kill Mario, kill touching sprite (fall / puff). Effects: smoke, glitter, shatter, erase block, change to tile, shake screen. Sound: play sound (named list per port), change music. Sprites: spawn sprite (vanilla/custom, extra bit, extra bytes 1–4, position, state, X/Y speed, facing). Level: set ON/OFF, water / slippery level, brightness, give coins, star power, blink invulnerability, stun Mario, disable buttons, set timer, end level, scroll lock, set powerup, start blue/silver P-switch. Advanced: Write RAM, Custom ASM.
Conditions — ON/OFF, Mario powerup, riding Yoshi, star, blue/silver P-switch, spin jumping, carrying, ducking, moving direction, really on top, Mario holds sprite X; sprite is number X (vanilla/custom), sprite state; RAM check. Logic: if / else if / else, AND, OR, NOT.

## Non-goals (v1)
Importing foreign GPS blocks (v2), Map16 tile graphics (v2), free-RAM one-shot guard (v2), AddmusicK custom sound names (later), per-project Libraries (later), emulator test integration (never planned), Piece icons, translated Pieces, running GPS/Callisto.

## Architecture

- **Shell**: Tauri 2 (Rust) — only file dialogs, file system access, and running Asar (the GPS project's `asar.dll`, ADR 4). Prefer official Tauri plugins (dialog, fs) over custom Rust; loading the DLL is the one custom command.
- **Front-end**: TypeScript + Vite + React; Blockly 11+.
- **`core/`** (framework-free TypeScript, no Tauri or DOM imports; the deep modules):
  - `template` — Mustache-subset renderer.
  - `library` — load/validate manifests (JSON Schema), merge built-in + user Library, resolve Pieces by id/version.
  - `model` — Block model types, versioned schema, migrations; Blockly-state ↔ model conversion lives in the UI layer, not here.
  - `generator` — `generate(model, library) → { text, lineMap }`; slot→offset mapping, condition wiring, register saves, labels, header.
  - `header` — `parse(text) → { model, checksumOk } | error`.
  - `listtxt` — parse / edit GPS `list.txt` preserving everything else; PIXI list reader.
  - `summary` — one-line Slot summaries.
- **UI**: `ui/` React components; Blockly block definitions generated from manifests; workspace ↔ model adapters.
- **Validation**: the GPS project's `asar.dll`, loaded by a Tauri command, on a temp harness file (ADR 4).

## Testing
- `core` with Vitest: template unit tests; generator golden files (every preset → expected `.asm`); header round-trip (generate → parse → equal model); property test: random models round-trip; `list.txt` edit tests on fixtures copied from a real project.
- Every preset and every Piece (with default params, in each allowed Slot) assembles with Asar in CI-style script.
- Manual QA in an emulator (HITL) for the facts marked unverified in the research.
